# Project Structure

## Directory Layout

```
BeamFinder/
├── configs/              # Configuration files
│   ├── dataset.yaml      # YOLO data paths and class definitions
│   └── spec.md           # Project specification document
├── data/
│   ├── raw/              # Original DeepSense Scenario 23 dataset
│   │   ├── unit1/camera_data/           # 11,387 source images (960×540 JPG)
│   │   ├── resources/bbox_labels_final/ # Ground-truth YOLO labels
│   │   └── scenario23.csv               # Metadata with beam indices
│   └── processed/        # Auto-generated YOLO-format dataset
│       ├── images/       # train/val/test image splits (symlinked)
│       └── labels/       # train/val/test label splits (symlinked)
├── notebooks/            # Jupyter/Colab versions of scripts
│   ├── build_dataset.ipynb
│   ├── train.ipynb
│   ├── classify.ipynb
│   └── detect.ipynb
├── output/               # Auto-generated training and inference outputs
│   ├── beam_model/       # Beam centroid CSV and pickle files
│   ├── detections.csv    # Final unified inference results
│   └── annotated/        # Visualizations with bounding boxes
├── paper/                # Reference paper (Charan et al.)
│   ├── paper.pdf
│   └── paper_reference.md
├── presentation/         # Demo slides and sample images
├── scripts/              # Core execution pipeline (run sequentially)
│   ├── build_dataset.py  # Step 1: Create YOLO splits
│   ├── train.py          # Step 2: Fine-tune YOLO26s
│   ├── classify.py       # Step 3: Generate beam centroids
│   └── detect.py         # Step 4: Run inference
├── best.pt               # Trained model weights (generated by train.py)
├── requirements.txt      # Python dependencies
└── README.md             # Project documentation
```

## Key Conventions

### File Organization
- **Scripts are executable**: All scripts in `scripts/` are designed to run from the repository root
- **Sequential pipeline**: Scripts must be run in order (build → train → classify → detect)
- **Auto-generated folders**: `data/processed/` and `output/` are created automatically
- **Symlinks for efficiency**: Dataset uses symlinks to avoid duplicating large image files

### Data Flow
1. Raw data lives in `data/raw/` (never modified)
2. Processed data goes to `data/processed/` (YOLO format)
3. Training outputs go to `runs/` (Ultralytics default) and `output/`
4. Best model weights are copied to root as `best.pt`
5. Final inference results go to `output/detections.csv`

### Naming Patterns
- Images and labels share the same stem (e.g., `image_BS1_10000_17_56_03.jpg` ↔ `image_BS1_10000_17_56_03.txt`)
- YOLO labels use normalized coordinates (class x_center y_center width height)
- Single class index: `0` for "drone"

### Configuration
- `configs/dataset.yaml`: YOLO data configuration (paths, class names)
- `configs/spec.md`: Detailed project specification and methodology
- Hyperparameters are hardcoded in `scripts/train.py`

### Code Style
- **Pathlib over os.path**: Use `Path` objects for file operations
- **Seed for reproducibility**: `random.seed(42)` for dataset splits
- **Fallback patterns**: Try symlink first, fall back to copy on Windows
- **Print progress**: Scripts output status messages for monitoring
- **Minimal dependencies**: Keep requirements lean (ultralytics, matplotlib)

## Important Notes

- All scripts assume execution from repository root
- Dataset must be placed in `data/raw/` before running pipeline
- Training requires GPU (designed for Lightning.ai A100)
- `best.pt` in root is the primary artifact for inference
